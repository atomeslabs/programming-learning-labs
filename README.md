# Programming Learning Labs

**Hands-on programming practice in C, x86/x64 Assembly, and Python.**

This repository documents my programming learning journey through small, practical projects, experiments, and exercises.

The goal is to progressively strengthen my programming fundamentals, develop a deeper understanding of low-level systems, and apply these skills to cybersecurity, reverse engineering, algorithms, mathematics, and other technical areas.

## Languages

| Language | Main learning areas |
|---|---|
| **C** | Fundamentals, pointers, memory management, bitwise operations, file I/O, and secure coding |
| **Assembly x86** | Registers, instructions, memory addressing, stack operations, and control flow |
| **Assembly x64** | 64-bit architecture, calling conventions, stack management, and C interoperability |
| **Python** | Programming fundamentals, scripting, automation, file processing, testing, and algorithms |

## Learning Methodology

My approach is based on practical, incremental learning:

1. Study a programming concept.
2. Implement a small program demonstrating that concept.
3. Compile or run the program.
4. Test its behavior and investigate errors.
5. Refactor or improve the implementation.
6. Document the results and lessons learned.

Each project may include source code, build instructions, usage examples, and tests.

## Application Areas

Projects may explore:

- **Cybersecurity:** secure programming, file analysis, and security-related utilities.
- **Reverse Engineering:** memory representation, low-level instructions, and binary analysis.
- **Algorithms & Mathematics:** data structures, numerical methods, and foundations for machine learning.
- **Trading:** numerical tools, risk calculations, and market data analysis.
- **Poker:** probability, expected value, and statistical simulations.

## Progress Tracking

Exercises and mini-projects are managed using GitHub Issues and GitHub Projects.

Typical workflow:

**Backlog → Todo → In progress → In review → Done**

A project is considered complete when its implementation has been tested and its documentation reflects the actual results.
